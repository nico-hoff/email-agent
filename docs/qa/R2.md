# QA R2: Postfächer in der App (ADR 0023, 0035)

Stand 2026-10-31, Branch `wt/r2`. Screenshots (synthetischer Dev-Modus, 390x844): `docs/qa/img/R2-*.png`. Vertrag: `docs/accounts-contract.md`.

## Was ist neu

- Profil → **Konten verwalten**: Liste (Bezeichnung, Farbpunkt, Typ, Worker-Status, letzter Test, „Passwort gespeichert seit …“), Konto hinzufügen (Google oder IMAP), bearbeiten, **Verbindung testen**, **Deaktivieren/Aktivieren**. Das Passwortfeld ist nie vorbefüllt, kein Passwort wird je angezeigt.
- Google-Vorgabe: `imap.gmail.com:993`, TLS an, Ordner `INBOX` und `[Gmail]/Spam`, Hinweis auf App-Passwörter.
- Passwörter liegen verschlüsselt (AES-256-GCM) in der Datenbank (`mail_accounts`, Migration 007), Schlüssel `ACCOUNTS_ENCRYPTION_KEY`. Ohne Schlüssel laufen keine Postfächer (Status „Angehalten: Schlüssel fehlt“), und Konten lassen sich nicht anlegen.
- Der Server startet, stoppt und startet Postfach-Worker selbst, wenn du Konten anlegst, änderst oder deaktivierst (Prüfung alle 15 Sekunden, kein Neustart nötig).
- Die alte Konten-Datei ist Legacy: einmaliger Import beim Start (oder `npm run accounts:import`), danach wird sie nie wieder gelesen.
- Neue Konten starten mit „Spam gelesen“ = **aus** (ADR 0025). Importierte Konten behalten ihren Modus (fehlend: Probelauf). Der Schalter dafür in der App kommt mit R3.
- Schlüsselwechsel: `npm run accounts:rekey`.

Screenshots: `R2-konten-liste.png`, `R2-konto-hinzufuegen-google.png`, `R2-verbindungstest.png`.

## Vor dem Deploy auf `main` (nur Nico)

1. **`ACCOUNTS_ENCRYPTION_KEY` als Secret setzen, bevor der erste Start mit Konten-Datei passiert.** Erzeugen: `openssl rand -base64 32`, im Passwort-Manager sichern (ohne den Schlüssel sind die Passwörter weg), GitHub Environment `prod` (siehe `docs/github-environments.md`) und lokal in `.env.local`.
2. Erster Start mit Schlüssel und vorhandener Konten-Datei: Log `legacy accounts file imported: N account(s)`. Im Profil prüfen: alle Konten da, Typ stimmt, „Passwort gespeichert seit …“ gesetzt, **„Verbindung testen“ pro Konto** (das öffnet eine echte IMAP-Verbindung, nur LIST; nur du entscheidest, wann).
3. Erst danach die Konten-Datei (und auf fly das Secret `ACCOUNTS_JSON`) entfernen.
4. Fehlt der Schlüssel beim Start, läuft die App ohne Postfächer weiter; die Datei bleibt unberührt und wird beim nächsten Start mit Schlüssel importiert.
5. Optional `ACCOUNTS_ALLOW_PRIVATE_HOSTS=1` nur, wenn ein Postfach auf derselben Maschine läuft (Mail-Bridge). Sonst bleibt es aus.

## Klick-Checkliste (iPhone)

1. Profil öffnen: Abschnitt „Konten verwalten“ mit deinen (importierten) Konten, jeweils Farbpunkt, Typ, Status.
2. „Konto hinzufügen“ → „Google (Gmail)“: Hinweis zu App-Passwörtern sichtbar, Server-Zeile „imap.gmail.com, Port 993, TLS an“, Spam-Ordner `[Gmail]/Spam`.
3. Bezeichnung, Farbe, Gmail-Adresse und App-Passwort eintragen → „Konto speichern“. Toast „Konto gespeichert.“, Konto erscheint in der Liste, Status „Verbindet …“ und nach wenigen Sekunden „Verbunden“ (oder eine klare Meldung).
4. „Verbindung testen“: „Verbindung erfolgreich“ bzw. verständliche Fehlermeldung (falsches Passwort: „Anmeldung abgelehnt“). Ergebnis bleibt als Hinweis „Test ok / Test fehlgeschlagen“ an der Karte.
5. „Bearbeiten“: Passwortfeld ist leer, Hinweis „Leer lassen, um das gespeicherte Passwort zu behalten“. Bezeichnung ändern, speichern: Passwort bleibt, Konto läuft weiter.
6. Neues Passwort eintragen und speichern: Konto verbindet neu (Status wechselt kurz auf „Verbindet …“).
7. „Deaktivieren“: Status „Deaktiviert“, keine neuen Mails mehr. „Aktivieren“: läuft wieder.
8. „IMAP“ statt Google: Server, Port, TLS (aus = Warnhinweis) sind einstellbar. `localhost` oder `192.168.x.x` als Server wird abgelehnt (Meldung zu gesperrten Adressen).
9. Zweiter Nutzer (Einladung aus R1): sieht keines deiner Konten und keine Mails davon.
10. Liste (Startseite): Mails neuer Konten erscheinen mit dem Farbpunkt, nachdem der Worker verbunden ist.

## Bekannte Grenzen

- Kein OAuth für Google, nur App-Passwort. Kein Löschen von Konten (nur Deaktivieren), keine Passwort-Anzeige.
- Änderungen wirken nach bis zu 15 Sekunden (Supervisor-Takt), eine Maschine.
- Host-Prüfung blockt private IP-Literale und lokale Namen, löst DNS-Namen aber nicht auf (ein Name, der auf eine private Adresse zeigt, wird nicht erkannt).
- Der Verbindungstest prüft Anmeldung und Ordnernamen (LIST), nicht das Lesen von Mails. Limit: 10 Tests je 10 Minuten.
- „Spam gelesen“-Schalter, Not-Aus und Tageslimit in der App folgen mit R3; bis dahin wird `spam_seen_mode` nur gespeichert (neue Konten: aus).
- TLS lässt sich ausschalten (mit Warnhinweis); sinnvoll nur im eigenen Netz.
- Im Demo-Modus (`npm run dev`) gibt es keine echten Verbindungen: Konten lassen sich anlegen (mit `ACCOUNTS_ENCRYPTION_KEY`), „Verbindung testen“ antwortet „Im Demo-Modus gibt es keine echten Verbindungen.“.
