# QA R1: Nutzerkonten (ADR 0022, 0033)

Stand 2026-10-31, Branch `dev`. Screenshots (synthetische Daten, 390x844): `docs/qa/img/R1-*.png`.

## Was ist neu

- Neuer Modus `AUTH_MODE=users`: Login mit E-Mail und Passwort (scrypt, mindestens 12 Zeichen), Sitzungen, die der Server widerrufen kann, Registrierung nur per Einladungscode.
- Seite `/profil` (⋯-Menü): E-Mail, Rolle, „Abmelden“, „Auf allen Geräten abmelden“, für Admins „Einladung erstellen“ (Code einmalig sichtbar) und offene Einladungen.
- Mandantentrennung: jede Abfrage filtert nach `accounts.user_id`; fremde IDs sind 404. Alle bisherigen Daten gehören Nutzer 1; der erste `user:create` übernimmt ihn.
- CLIs `npm run user:create` und `npm run user:invite`. `fly.toml` setzt `AUTH_MODE = 'users'`.
- Nebenbei behoben: Im Produktionsmodus war das Stylesheet (`/_vf/css/`) ohne Login gesperrt, die Welcome-Seite sah ungestylt aus.

Screenshots: `R1-welcome-login.png`, `R1-welcome-register.png`, `R1-menu-profil.png`, `R1-profile.png`, `R1-profile-invite-created.png`.

## Vor dem Deploy auf `main` (nur Nico)

1. Deploy bringt `AUTH_MODE=users`; bis ein Admin existiert, kommt niemand rein (auch nicht mit `APP_PASSWORD`).
2. Direkt nach dem Deploy: `fly ssh console`, dort `su node -s /bin/sh -c "node scripts/user-create.ts --email DEINE@MAIL"` (Passwort wird ohne Echo abgefragt). Als `node`, nicht als root, sonst gehören die SQLite-Dateien root. Das übernimmt Nutzer 1: alle Daten bleiben bei dir.
3. Optional vorab lokal testen: `AUTH_MODE=users npm run dev:live` (echte DB nur mit deiner Freigabe).

## Klick-Checkliste (iPhone)

1. App öffnen: Anmeldeformular mit E-Mail und Passwort, Link „Mit Einladungscode registrieren“. Falsches Passwort zeigt „E-Mail oder Passwort stimmt nicht.“
2. Mit deinem Admin anmelden: Mails und Briefing wie vorher (alle Daten da).
3. ⋯ → Profil: E-Mail, Rolle Admin, „1 aktive Sitzung“.
4. „Einladung erstellen“ (Rolle Nutzer): Code erscheint einmal. Seite neu laden: Code weg, Eintrag in „Offene Einladungen“ ohne Code.
5. Zweites Gerät/Privatfenster: „Mit Einladungscode registrieren“, Code, E-Mail, Passwort (12+). Danach leere Liste, nichts von dir sichtbar.
6. Denselben Code erneut benutzen: „ungültig, abgelaufen oder schon benutzt“.
7. Zweiter Nutzer: Profil zeigt Rolle Nutzer, keinen Einladungsabschnitt.
8. Zweiter Nutzer „Auf allen Geräten abmelden“: Weiterleitung zur Anmeldung; altes Cookie funktioniert nicht mehr.
9. Du: „Abmelden“, dann wieder anmelden.

## Bekannte Grenzen

- Kein Passwort-Reset, keine E-Mail-Bestätigung, keine Zwei-Faktor-Anmeldung, kein UI zum Sperren von Nutzern.
- Rate-Limits liegen im Speicher je Prozess (eine fly-Maschine).
- Passwort- und Tailnet-Modus bleiben als Übergang und zeigen im Profil nur einen Hinweis; sie bilden auf Nutzer 1 ab.
- Das Agenten-Tool bekommt den Nutzer aus dem asynchronen Kontext der Anfrage; ohne ihn antwortet es wie bei einer unbekannten Mail.
- Konten der Konten-Datei gehören Nutzer 1; Konten pro Nutzer in der UI folgen mit R2.
