## 3. fly.io: was auf `main` liegt

- `fly.toml`: `fra`, `shared-cpu-1x` 512 MB (gemessen, 256 MB reichen nicht), Auto-Stop aus, kein Auto-Start (Not-Aus = Machine stoppen), Volume `email_data` → `/data`, Health-Check `/api/health`.
- Dockerfile-Stages `base` / `fly` (startet als root, `scripts/docker-entrypoint.sh` setzt `/data` auf `node:node` 0700 und wechselt per `setpriv` dauerhaft auf `node`) / `app` (Standard, `USER node`, Compose und Docker-Smoke).
- Start-Schutz `lib/fly-guard.ts`: ist `FLY_APP_NAME` gesetzt, startet der Server nur mit `APP_PASSWORD` ≥ 16 Zeichen.
- Anleitung mit Kosten, Snapshots, Not-Aus, Konten-Datei-Optionen: **`docs/fly-deploy.md`**.
- Offen: App-Name `email-agent` frei? Preis für 512 MB in `fra` vor dem Deploy prüfen. RAM nach Betrieb mit echten Konten nachmessen. Volume-Besitzer beim fly-Mount nur per Forum belegt (Entrypoint macht es robust).
- fly-Login: flyctl lag nur in diesem Container. In einer neuen Session neu installieren (https://fly.io/agent-ready.md), `fly auth login` bestätigt Nico.

## 4. fly.io-Inbetriebnahme (Kurzfassung von `docs/fly-deploy.md`)

1. `fly apps create email-agent` (kein `fly launch`, das überschreibt `fly.toml`).
2. `fly volumes create email_data --region fra --size 1`.
3. **Nico** setzt Secrets selbst: `fly secrets set APP_PASSWORD=… OPENROUTER_API_KEY=…` (≥ 16 Zeichen, nie im Chat).
4. `fly deploy`, `fly scale count 1`.
5. Prüfen: Welcome zeigt Passwortfeld; `curl -s -o /dev/null -w '%{http_code}' https://<app>.fly.dev/api/emails` → `401`.
6. Erst danach: Konten-Datei auf das Volume (Nico, z. B. `fly ssh sftp`), `auto_actions` bleibt `dry_run`.
