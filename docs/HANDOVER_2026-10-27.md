## 6. Stolpersteine (alle selbst erlebt)

1. **UI ohne Farben:** Veryfronts CSS-Scanner liest alle `.ts/.tsx/.js` im Projekt und ignoriert nur `node_modules` im Projektwurzelverzeichnis. Agent-Worktrees unter `.claude/worktrees/*/node_modules` sprengen das Limit (100 000 Kandidaten) → gar keine Styles. `npm run dev` warnt jetzt. Lösung: alte Worktrees nach Prüfung auf ungesicherte Arbeit mit `git worktree remove` entfernen. Für Subagenten deshalb Worktrees nach dem Übernehmen sofort aufräumen.
2. **POST → 403:** Veryfronts eingebauter Double-Submit-CSRF (`__Host-vf_csrf` Cookie + Header `x-csrf-token`) gilt in Dev und Produktion. Client nutzt `csrfMutationHeaders` aus `veryfront/index.client`; unser eigenes Token läuft unter `x-app-csrf`.
3. **Veryfront-Loader:** API-Routen und Tools werden gebündelt (`/tmp/vf-discovery-*`); `import.meta.url`/`PROJECT_ROOT` zeigen dort nach `/tmp`. Keine JSON-Imports in Tools; dynamische Objekt-Lesezugriffe `obj[key]` in Modulen, die Routen importieren, brechen den Loader → `Map` verwenden.
4. **Agent-ID:** Veryfront leitet `replyDrafter` aus `agents/reply-drafter.ts` ab. Außerhalb des Servers findet Veryfront keine Projekt-Tools (die Probe läuft daher ohne Tool).
5. **`node_modules` nie symlinken** (API-Routen → 500).
6. **Node exakt 26.12.1** (`.nvmrc`), sonst STOP-1.
7. **Schema-Validator:** `defineSchema(...)()` in Tools braucht den von Veryfront beim Start registrierten Validator; Tests laden ihn per internem Pfad (bei Veryfront-Updates prüfen).
8. **Eval-Daten:** Das große HF-Set (`triage`) enthält entgegen der Karte keinen Spam und keine Newsletter, nur personal/phishing/business-nahe Klassen. `is_spam` wird daher nur über Phishing gegen Geschäftsmails geprüft; Werbe-Spam (web.de-Hauptfall) kalibriert nur Nicos echtes Sample.
9. **`eval:compare`** liest nur `data/eval-runs/*.json` (nicht Unterordner). Kalibrier- und Testläufe getrennt halten (siehe `docs/LOCAL_DEV_MAC.md`, Abschnitt 6).
